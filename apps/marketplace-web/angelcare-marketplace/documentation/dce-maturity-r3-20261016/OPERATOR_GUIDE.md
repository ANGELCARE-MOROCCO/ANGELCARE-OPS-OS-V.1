# Digital Customer Experience · Maturity R3

This release completes the audited operator gaps on the 20261016_112516 source. It keeps the existing light DCE visual language, all 23 destinations, sixteen functional families, sixty-four mode contracts and native Marketplace authorities. It adds no public DCE discovery route or public upload endpoint. The original PDF/image interpretation remains governed by the locked R1 doctrine and its child/family audience amendment.

## Enter and orient

Open the existing **Digital Customer Experience** sidebar entry. The outer sidebar continues to collapse within the native admin shell. The dashboard uses managed topics, complete server-side publication filters, every family in its scrollable legend, and two explicitly labelled groups of eight publishing bars. Ranking has an explicit metric and counts the full requested event period. Empty traffic/revenue remains empty; staff previews are not customer evidence.

## Operate from a dossier

Open **Connected dossier** inside an editor. It shows the actual source revision, translation coverage, linked dependencies and reverse usage, native media/offer counts and release history totals. Open a related dossier or continue to content, media, templates, journeys, publication, access, analytics, reports, logs or reception with the dossier reference retained in the URL. Private destinations remain governed by native permissions. If the editor is dirty, a recovery draft is retained and leaving requires an explicit choice.

Context is applied on the server for connected inventories, releases, logs and analytics. The advertising inspector loads the dossier family, audience, topic and template. Native Media remains a shared vault: the connected DCE asset registry is filtered separately. Imports are receipt-based workflows; a context indicator does not silently restrict or change the records named in a CSV. Read the prepared changes before applying a batch.

## Author and validate each family

The sixteen existing specialised editors remain the authoring authority. Utilities now exposes a family/mode inspector with exact collection fields, localisation rules, reference types and the canonical mode contract. The family-targeted links lead to its registry and import preparation.

Translation readiness examines required/supplied text fields and localised collection content, rather than a title alone. A required language with missing content blocks release with the field path. The default language can use native root content; translations require their own values. Studio previews still use the actual family definitions, bindings and action contracts. Assessment answers and private operational data stay outside public manifests.

## Configure world defaults

Only the `world-defaults` setting edits the world policy. Enabled family controls govern new experiences, templates and new create imports; existing dossiers stay editable. Legacy empty family selection means all families until an operator makes an explicit selection. Explicitly disabling every family prevents new creation.

Enabled languages must include the default. Existing translations are retained. Accent and signature seed new compositions; the signature also appears in DCE navigation. Concurrency governs 1–4 concurrent native editorial-media uploads. Scheduling and rescheduling convert from the configured IANA timezone, rejecting ambiguous or nonexistent DST wall times. Retention remains a declared policy: nothing purges customer data automatically.

## Publish and recover

Save → validate → review → approve → release or schedule the exact revision. Existing immutable releases and version conflict controls remain in force. Due processing validates dependencies using release scope, without impersonating a staff member. One failed release does not abort the remainder. Outcomes distinguish publication, blocked validation and retry-pending failures. Existing live releases remain protected.

Use **Logs & maintenance** or notifications for complete scoped queue counts. Open the owning workspace to inspect its exact receipt. Queue counts are recorded evidence; configured credentials are not proof that a worker ran. The existing publication worker is reused. No new worker/resource is created by this patch.

## Receive and handle private files

In an upload-enabled form, use **Select protected DCE receiver** to initialise/select the owned receiver without typing an ID. Alternatively initialise it in Settings and use the reference picker in the form's native `privateReceiverId` field. It can be enabled/disabled in its own setting editor. Forms must declare allowed PDF/JPEG/PNG/WebP types and a file limit no greater than 20 MiB. Publication verifies that the receiver belongs to the same scope and that the existing signed S: gateway is configured.

In Messages & assistance, select a received case. The protected attachment area can upload a private file through the existing signed gateway, verify its checksum/type/size and attach it with case revision protection. A verified receipt survives a link conflict and can be completed after reloading the case. The browser retains the latest pending receipt reference for recovery.

Download requests authenticate the operator and recheck moderation permission, case scope and linked receipt. Responses are private/no-store, attachment-only and nosniff. Customer documents are never registered in the public editorial media catalogue. Case attachments are limited to ten linked files; pending preparations are bounded per actor. This is a workflow guard, not a provider storage quota.

Future public customer contracts verify native customer ownership, current release, active access rules, exact file field and checksum, then atomically create the case and claim receipts. They are server-only preparation for Chapter 2. Native Hotline/Academy/B2B destinations continue to require their own native receipt; DCE does not fabricate one.

Cases with retained attachment receipts remain protected from permanent deletion. This release does not add automatic file destruction, antivirus scanning, OCR, transcription or transcoding. Source inspection and rights management remain with the owning media authority; upload supported renditions where required.

## Advertising and commerce

The existing fifteen-format atlas, policy hierarchy and provider adapters remain. The inspector now receives dossier context; native display units must have fresh observed active evidence and local enablement. Google approval and specialist-program eligibility remain provider decisions. No advertising script runs in admin previews. No sales, payments, enrolments, identity records or funds are created by these admin completion controls.
