# ANGELCARE BUILD 360 — Mega ZIP 02

**Contract:** Territory OS Core & Global Expansion Layer  
**Build root:** `apps/ops-web/angelcare-marketplace`  
**Cumulative baseline:** Mega ZIP 01  
**Execution boundary:** No build, Git action, deployment or database migration is performed by the delivery package.

## Binding outcome

Territory OS is the governed expansion machine, not a country settings table. Territory 1 is the controlled master operational world. Territory 2+ can be created or cloned with explicit inheritance, local override shells, launch gates, owners, reviewers, lifecycle controls, health evidence and territory-isolated access.

## Mandatory product surfaces

- Territory Command executive cockpit and portfolio registry.
- Create and Clone Territory wizards.
- Territory dossier, settings, inheritance/override studio, readiness board, health timeline and governed preview.
- Persistent records, standard APIs, server-side authorization, audit and export.
- Lifecycle: `draft → configuring → review → soft_launch/live → paused → archived` with validated transitions.
- Live launch blocked while mandatory gates remain incomplete.

## No-go conditions

No mock cloning, fake readiness, client-only persistence, global lock bypass, cross-territory leakage, generic card-grid delivery, silent future-module simulation, hidden dependency or unaudited sensitive action.
