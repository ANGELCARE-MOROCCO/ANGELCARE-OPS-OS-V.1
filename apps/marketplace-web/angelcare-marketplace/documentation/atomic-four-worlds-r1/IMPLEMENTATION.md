# AngelCare — Four Atomic Worlds R1

Four editable Studio compositions built from reusable public-data components. Product Atelier has 25 sections, Care Constellation 20, Learning Odyssey 19, Solution Command 19. Each section is conditional: missing/empty sources remove its heading, content, gap and local navigation anchor. Zero and false remain real values.

## Customer experience

- Product: complete fitted media, thumbnails and keyboard-accessible zoom; learning and contents discovery; required variant combinations; real price/stock; bounded quantity; guarded basket add; published delivery/support; evidence/reviews only with sources; canonical related offers and distinct bundle/accessory/alternative rails.
- Service: one-time and recurring native field coverage; published day preferences and weekly rhythm; date/time intent; service scope, plans and provider projections; preference handoff into the category-native booking configurator. The rhythm preview is not a confirmed availability calendar.
- Academy/admission: outcomes, curriculum and modules, public trainers, actual cohort choices, published admission and credential fields. Cohort identity, ownership, open status, capacity and enrollment windows are checked again at configuration, revalidation and commit boundaries.
- B2B: organisational fit, selectable published scope fields, programme capabilities, deployment, operational/commercial/privacy/evidence fields, native solution configuration. Existing backend doctrine remains responsible for quotation, subscription or assessment outcomes.
- French/English/Arabic, RTL, mobile decision dock, reduced motion, keyboard controls, item-scoped 24-hour session draft and bounded URL handoff. No artificial countdown, fake scarcity, rating, certification or transaction success.

## Architecture and protected authorities

The generic engine is registered through Puck, the existing Studio published renderer, typed public bindings, World Factory compiler/materializer and existing native configurator. It is not four hardcoded production templates. JSON determines ordering, localized editorial copy, layouts, source keys, native field groups and conditional visibility. Legacy roots without atomicExperienceVersion=1 retain their existing renderer and defaults, including when opened in Studio.

The source patch makes eleven additive integrations. Native schema registry, import engines, category definitions, discovery readers, transaction authority, route resolver and assignment precedence remain unchanged. Native customer intent is extended and validated at the configurator boundary. Related offer reads are bounded, territory-compatible and published-only. Raw attributes, metadata and fulfillment notes are stripped at the new client boundary.

Homepage, shell/header/footer, Families, Home Services and the completed storefronts are outside the payload.

## Activation

Install the code patch; stage/commit/push it and run the canonical remote Marketplace GHCR workflow; deploy its exact SHA/digest through Coolify. Then open /angelcare-marketplace/admin/public-experience-authority/world-factory. Import each dedicated ZIP separately, compile it, compare desktop/mobile references against a real published compatible offer, attest the review, publish, and assign at the intended domain/schema/item scope. The installer does not write to your database, change published assignments or automatically replace an active theme. Existing more-specific assignments keep precedence.

The included references are actual renders of this code with synthetic QA fixtures; no fixture offers are installed. Live database integration, registry delivery, production mail and deployed customer transactions have not been verified by this patch. Remote full image build and deployed storefront checks remain release gates.
