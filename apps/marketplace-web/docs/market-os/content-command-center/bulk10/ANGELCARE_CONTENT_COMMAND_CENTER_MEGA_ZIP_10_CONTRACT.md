The Content Command Center is AngelCare’s internal content intelligence, strategy, production, review, distribution, publishing, performance and institutional-learning operating system.

The AI Director is a senior internal content executive. It must move real content work forward rather than behave as a chatbot, a recommendation panel or a blocker generator.

Its governing lifecycle is:

```text
Strategic objective

→ brief

→ validation preparation
```

## 3. Zero-dead-end doctrine

No provider, model, source, evidence or permission problem may strand the user.

Every unavailable capability must return at least one immediately usable continuation route:

- retry;
- switch provider;
- change model;
- continue without external research;
- use internal sources;
- create a human task;
- attach an existing asset;
- use manual production;
- authorize an override;
- defer only that capability;
- cancel the operation without cancelling the dossier.

A provider outage degrades one capability, not the complete Content Command Center.

## 4. Blocker taxonomy

### 4.1 Advisory warning

The user may continue. The interface explains the risk and offers inspection, delegation or dismissal.

### 4.2 Governed gate

The normal path expects a condition, but an authorized user may resolve, replace, waive, restrict, delegate or override it.

### 4.3 Technical impossibility

The provider action cannot execute, but the system must expose manual or alternative execution and keep the dossier editable.

No disabled control is acceptable without explanation and a resolution route.

## 18. Permanent deletion contract

Permanent deletion is a real server mutation, not a decorative button.

It requires:

- `market_ai.purge` or privileged authority;
- record disabled or archived;
- no active request;
- no protected dependency;
- explicit reason;
- exact typed confirmation;
- server-side enforcement;
- visible success or precise refusal.

A refusal must identify the dependency or state that must be resolved.

## 19. Edit and override contract

Edit and override are distinct.

Edit changes an allowed configuration under normal governance.

Override records an exceptional human decision, its reason and the resulting route. It must not silently erase the prior assignment configuration or historical requests.
