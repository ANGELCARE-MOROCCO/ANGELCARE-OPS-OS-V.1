This is an operator guide to the implemented source checkpoint. It is not release approval. No JOBKIX migration has been executed against a hosted database, and no live edition has been published.

The source uses the existing authenticated identity. `/jobkix/en/hiring/organization` starts a private employer context. The organization selector keeps each operating journey in an explicit organization. Household aliases and approximate geography are public fields; exact addresses and contact details stay in the private identity section. Public profile changes require a new review. Legal identity or country changes also revoke the previous identity review.

In `/jobkix/en/hiring/vacancies/new`, choose native published setting/profession records and an authorized site, supply the employment terms and declarations, and add stable screening questions. Saving a private server draft does not publish a vacancy. A lost acknowledgement is recovered with the saved request key before editing resumes. Site-scoped recruiters receive only their current authorized site choices.

The vacancy overview provides a private preview of the saved revision, editing, revision history and publication actions. Submit the complete draft for moderation. An authorized operator in the existing administration must approve the exact revision. Publication also requires a currently reviewed organization identity, approved public profile, active site when assigned, and a future closing instant. Supply a local date/time and explicit IANA timezone. Ambiguous/nonexistent daylight-saving times are rejected rather than silently adjusted.

Pause, closure, reopening, archiving and duplication require reasons. Reopening requires another moderation/publication cycle. Duplication creates a private record and new question IDs; it retains neither publication nor review approval. Public historical reads retain the last published snapshot while private text/questions are edited. New applications stop immediately when canonical eligibility fails.

The applications inbox uses submitted profile/CV/answer snapshots. Later profile changes do not replace them. Inspect the evidence and confirm a permitted stage change. Moving away from the offer stage withdraws outstanding offers; ending an application cancels its open interviews. A stage control cannot record candidate acceptance. The comparison screen supports up to three authorized application snapshots and does not rank or reject candidates. The pipeline supports accessible board/list presentations and atomic, explicitly reviewed group changes, with at most 24 selected applications and no automatic rejection. Current versions and permissions are rechecked for every application; a lost acknowledgement uses the original saved key. Rendered interaction acceptance remains pending.

Recruitment messages retain their original language. They are stored durably; an email transport acknowledgement is not implied. A pending message remains frozen for same-key recovery. Blocking an organization or suspending it prevents new messages/acceptance while preserving candidate history.

Use the interview or offer action from the selected application to keep the recipient and vacancy context. Interviews use UTC instants plus an explicit IANA timezone, current scoped panel choices, candidate responses and authorized calendar downloads. Rescheduling resets the candidate response. Completion is available only after the scheduled end. Confidential evaluation is separate from the candidate-visible conversation. Assigned panelists can read submitted evidence for assigned interviews; current membership, candidate blocking and assignment removal remain effective. An assigned panel member can accept or decline the invitation independently of the candidate response. Declining removes access to submitted evidence and its file. Panel responses are retained in revision snapshots. Full panel-history presentation and rendered lifecycle acceptance remain pending.

Offers have saved exact terms, declared pay when supplied, an optional start instant and an optional response deadline. Save changes before sending. Review the exact saved revision and recipient, then explicitly send it. Only the authenticated intended candidate can accept or decline a current offer. Notification failure does not undo a committed recruitment record. Guarded operational dispatch, bounded scheduled processing and native D07 known-failure recovery are implemented but not configured, invoked or certified against hosted email transport. Unknown acknowledgements are not resent.

There is no copy-paste installation command for a completed product yet. The source-stage installer tools in `scripts/jobkix/installer/` require the final generated payload and manifest. Their fixture tests do not install this checkpoint into any live repository. The completed package must provide its own tested apply/rollback commands, final archive size and SHA-256.

All seven interface languages have authored strings; no native-language review is claimed. Initial rendered desktop/mobile/RTL evidence and a passing isolated connected browser recruitment journey exist; no complete screen-family or full A–H acceptance is claimed. The original approved color/reversed logo and icon have been located, preserved and integrated through deterministic derivatives. Local development tests are now user-authorized. The 16-check native navigation suite passed local language context, Arabic widths/shortcut placement and Marketplace favicon/document-attribute restoration. Final full-screen acceptance and hosted service checks remain pending.

H13 institutional sites use native 24-record pages. Edit links preserve the selected organization and address a site directly by URL. Save a private server draft before leaving when needed. Reopening the same new-site/editor URL restores access to that draft; restoration of an older draft requires reviewing the current site version. An interrupted submission retains its original effect key and resolves the canonical receipt before allowing another create/save. Revoking organization-management membership removes access to its drafts and receipts. No browser storage is used.

Organization, site, vacancy and talent-pool selectors use searchable native 24-record pages. Selected records remain independently addressable when outside the current page. Choosing another organization never grants access to its private records. Interview panels use the same native paging pattern, scoped to the application and its current vacancy/site authority. Select at most 20 members. Saved private interview drafts restore the exact selected IDs and meeting fields. A lookup failure retains input and offers retry; a member removed after selection is still rejected by the canonical interview command. Existing interviews and offers have separate, correctly labelled revision histories. These source features passed isolated SQL and local browser checks; hosted integration and full family acceptance remain pending.
